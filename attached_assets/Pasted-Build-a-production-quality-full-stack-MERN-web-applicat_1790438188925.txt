Build a production-quality full-stack MERN web application called **TraceBack — Smart Lost & Found Network**.

TraceBack is a modern digital platform that helps people recover lost belongings by connecting people who have lost items with people or organizations that have found them.

The application should go beyond a basic classified-listing website.

The key feature is a **Smart Matching Engine** that analyzes lost and found reports using multiple attributes such as category, location, date/time, description, color, brand, approximate dimensions, and other characteristics to identify potentially matching reports.

The platform should also include a **secure ownership verification workflow** so that a person cannot simply claim an item using publicly visible information.

The final product should look and feel like a real startup-quality web application rather than a college CRUD project.

# 2. Main Problem

People frequently lose:

* Phones
* Wallets
* Bags
* ID cards
* Keys
* Earbuds
* Laptops
* Documents
* Jewelry
* Books
* College belongings
* Other personal items

Existing lost-and-found systems generally depend on users manually searching through posts.

TraceBack should instead proactively identify potentially matching lost and found reports.

Example:

User A reports:

"Lost a black JBL wireless headphone case near Kashmere Gate Metro around 6 PM."

User B reports:

"Found black JBL earbuds case near Kashmere Gate around 6:20 PM."

TraceBack should identify these as a potential match and notify both users.

Do NOT automatically declare that the item is a match.

Instead show:

**Potential Match Found**

with a match confidence score and relevant shared attributes.

# 8. Privacy-Preserving Listings

This is an important feature.

When someone reports a found item, the system should generate:

### Public Information

Information safe for everyone to see.

### Private Verification Information

Information that only the finder/organization and authorized verification system can access.

For example:

Public:

"Black leather wallet with multiple cards."

Private:

"Contains a blue SBI card and a specific photograph."

The claimant can later be asked:

**"Describe one private characteristic of the item that was not publicly displayed."**

This helps prevent fraudulent claims.

# 9. Smart Matching Engine

Create a backend matching service.

When a new lost/found report is created, compare it against relevant existing reports.

Calculate a matching score using attributes such as:

* Category similarity
* Brand similarity
* Color similarity
* Location proximity
* Date proximity
* Time proximity
* Description similarity
* Model similarity
* Distinguishing characteristics

Example conceptual scoring:

Category → 20%
Location → 20%
Time/date → 15%
Brand → 15%
Color → 10%
Description → 10%
Other characteristics → 10%

The exact weights should be configurable in the backend.

Do not call the score "probability."

Call it:

**Match Compatibility Score**

Example:

Potential Match
Compatibility: 87%

Shared attributes:

✓ Same category
✓ Same brand
✓ Similar location
✓ Same date
✓ Similar description

Differences:

! Reported 35 minutes apart

---
